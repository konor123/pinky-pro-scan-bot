# Pinky Tail — 꼬리잡기 SW 개발 계획서 v1.0

- 과제: Pinky Pro 2대의 꼬리잡기
- 요구: 기본 자율주행, 상대 엉덩이의 LED 추적, 초음파 센서로 태깅 감지, 태깅 시 부저
- 기반: Pinky Pro 공식 저장소 `pinklab-art/pinky_pro`, 로봇에 설치된 `pinkylib`
- 범위: 소프트웨어 개발과 시험 도구

---

## 1. 로봇이 하는 일

1. 두 로봇이 엉덩이의 LED를 꼬리색으로 켜고 벽으로 둘러싼 경기장을 돌아다닌다.
2. 앞 카메라 영상에서 상대의 꼬리 LED를 찾는다.
3. 꼬리가 보이면 쫓아간다. 두 로봇 모두 쫓는 쪽이면서 쫓기는 쪽이다.
4. 상대 꼬리에 붙어 앞쪽 초음파 거리가 태깅 거리 이하가 되면 태깅이다. 먼저 태깅한 로봇이 이긴다.
5. 태깅되면 두 로봇이 멈춘다. 이긴 로봇은 부저를 울리고, 진 로봇은 꼬리 LED를 끈다.
6. 제한 시간(초기값 3분) 안에 태깅이 없으면 무승부다.
7. PC에서 시작·정지 명령을 보낸다.

## 2. 로봇에서 확인한 것

로봇 1대(`pinky-pro`)에서 확인했다.

| 항목 | 확인 내용 |
|---|---|
| 꼬리 LED | WS2812B 8개, 로봇 뒤쪽 위(중심에서 뒤로 약 64 mm, 높이 약 78 mm, 폭 약 58 mm). `pinkylib.LED`의 `fill((r, g, b))`, `clear()`로 켜고 끈다 |
| 카메라 | ov5647, 로봇 앞쪽에서 정면을 본다. Picamera2 640×480에서 67 fps. 영상이 180° 뒤집혀 나온다 |
| 초음파 | 로봇 앞면 아래쪽 중앙. 20 Hz. 고정된 물체를 60초 쟀을 때 1,200개 중 13개가 0.21 m에서 0.89 m로 튀었다 |
| 부저 | GPIO 4. `battery_buzzer.py`(배터리 저전압 경고)가 울릴 때만 핀을 잡았다가 놓는다 |
| LiDAR | `/scan` 10 Hz, 360°, 0.5° 간격, 최소 거리 0.05 m |
| 컴퓨터 | Raspberry Pi 5, RAM 2 GB(bringup 실행 중 여유 약 920 MB). `ultralytics`와 `torch`가 설치돼 있지 않고 Hailo 장치가 없다. OpenCV 4.10 설치됨 |
| 모터 드라이버 | 명령이 끊겨도 직전 속도로 계속 달린다 |
| ROS | Jazzy, `ROS_DOMAIN_ID=0` |

두 번째 로봇은 아직 확인하지 못했다.

## 3. 동작 원리

### 3.1 꼬리 LED 인식

- 카메라 노출과 게인을 고정해 영상을 어둡게 찍는다. LED만 밝게 남는 영상에서 꼬리색 덩어리를 찾는다.
- 덩어리에서 두 값을 구한다.
  - **방향:** 덩어리 중심의 가로 위치 → 정면 기준 각도
  - **거리:** 덩어리 폭 → 거리. 거리별 폭을 측정해 변환표를 만든다
- 결과는 매 영상마다 발행한다. 꼬리가 없으면 '미검출'로 발행한다.
- 꼬리색, 노출, 색 범위, LED 밝기는 §6의 측정으로 정한다.

### 3.2 자율주행

지도와 Nav2 없이 LiDAR로 벽을 피하며 돌아다닌다.

- 앞이 비어 있으면 직진한다.
- 앞쪽에 물체가 가까워지면 서서, LiDAR에서 더 넓게 열린 쪽으로 제자리 회전한 뒤 다시 직진한다.
- 일정 시간마다 제자리에서 한 바퀴 돌며 꼬리를 찾는다.

### 3.3 추격과 태깅

1. **추격:** 꼬리가 검출되면 그 방향으로 몸을 돌리며 전진한다. 전진은 최근 0.3초 안에 검출이 있을 때만 한다.
2. **접근:** 검출 거리나 초음파 거리가 접근 거리(초기값 0.5 m) 이하가 되면 저속(초기값 0.10 m/s)으로 줄인다. 이때부터는 꼬리가 정면 ±7°(초음파가 보는 범위) 안에 있을 때만 전진하고, 벗어나면 제자리에서 돌아 맞춘다.
3. **태깅:** 다음 두 조건이 함께 3회 연속 성립하면 태깅이다.
   - 초음파 거리가 태깅 거리(초기값 0.10 m) 이하
   - 최근 0.5초 안에 꼬리가 화면 중앙에서 근접 크기 이상으로 검출됨
4. 미검출이 1초 넘게 이어지면 마지막으로 본 방향으로 제자리에서 돌아 보고, 다시 보이지 않으면 §3.2로 돌아간다.

꼬리 조건이 벽과 로봇을 구분하고, 상대의 앞·옆과 뒤를 구분한다. 꼬리가 어느 방향에서 보이는지는 §6의 1번 측정으로 확인한다.

### 3.4 마주쳤을 때

- 앞에 물체가 있는데 꼬리가 검출되지 않으면 벽과 똑같이 다룬다. 서서 열린 쪽으로 돌아 나간다. 태깅은 없다.
- 두 로봇이 서로 맴돌기만 하면 제한 시간에 무승부로 끝난다.

### 3.5 태깅 후

- 이긴 로봇: 정지 → 태깅 메시지 전송 → 부저 2번 → 0.15 m 후진(0.05 m/s). LiDAR 뒤쪽이 막혀 있으면 후진하지 않는다.
- 진 로봇: 태깅 메시지를 받으면 정지하고 꼬리 LED를 끈다.
- PC는 태깅 메시지를 받으면 두 로봇에 정지를 보낸다. 로봇 사이 메시지가 끊겨도 진 로봇이 멈춘다.
- 다음 판은 PC의 시작 명령으로 시작한다. 진 로봇이 먼저 출발하고, 이긴 로봇은 3초 뒤 출발한다.

### 3.6 두 로봇의 연결

- 두 로봇과 PC를 같은 공유기에 연결한다.
- 로봇마다 `ROS_DOMAIN_ID`를 다르게 준다. 두 로봇 모두 기본값이 0이라 그대로 두면 `/cmd_vel`이 섞인다.
- 로봇 사이와 PC 사이에는 게임 메시지만 UDP로 주고받는다.

| 메시지 | 보내는 쪽 → 받는 쪽 | 주기 | 내용 |
|---|---|---|---|
| 태깅 | 이긴 로봇 → 상대 로봇, PC | 응답을 받을 때까지 반복 | 판 번호 |
| 시작·정지 | PC → 두 로봇 | 2 Hz로 계속 | 경기 중 / 정지, 판 번호, 남은 시간 |
| 상태 | 로봇 → PC | 2 Hz | 상태, 검출 결과, 초음파 값 |

## 4. 소프트웨어 구성

패키지는 `pinky_tail` 하나다. 로봇에서 실행한다.

| 구성 요소 | 하는 일 |
|---|---|
| `tail_tracker` | 카메라를 혼자 쓴다. 영상을 180° 돌리고 꼬리색 덩어리를 찾아 방향·거리를 발행한다 |
| `tail_core` | 돌아다니기·추격·접근·태깅 판정 상태기계와 안전 규칙(ROS 비의존) |
| `tail_player` | 로봇마다 1개. 검출 결과·초음파·LiDAR를 받아 `tail_core`를 돌리고 `cmd_vel`을 낸다. 꼬리 LED와 부저를 다루고 게임 메시지를 주고받는다 |
| `tail_referee` | PC에서 실행(ROS 불필요). 시작·정지 명령, 제한 시간, 두 로봇 상태와 승패 기록 |
| 2D 모의 시험 | `tail_core` 두 개를 평면 운동 모델에 연결해 경기를 돌린다. GCE에서 실행 |
| 측정 스크립트 | §6의 측정과 기록 |

- 꼬리 LED는 `tail_player`만 `pinkylib.LED`로 다룬다. `pinky_lamp_control`, `pinky_led` 노드는 실행하지 않는다.
- 부저는 울릴 때만 GPIO 4를 잡았다가 놓는다. `battery_buzzer.py`의 저전압 경고가 계속 동작한다. 핀이 사용 중이면 잠시 뒤 다시 시도한다.

**패치와 실행**

| 대상 | 현재 동작 | 조치 |
|---|---|---|
| `pinky_bringup/bringup.py` | 명령이 끊겨도 직전 속도로 계속 주행 | 마지막 명령 이후 0.5초가 지나면 정지 |
| `pinky_sensor_adc` | 기본 실행에 없음 | 경기용 launch에 추가 |

**토픽 (로봇 1대 안)**

| 토픽 | 타입 | 생산 → 소비 |
|---|---|---|
| `tail/detection` | geometry_msgs/PointStamped (x 거리, y 방향, z 덩어리 폭. 미검출이면 z = 0) | tail_tracker → tail_player |
| `us_sensor/range` | sensor_msgs/Range | pinky_sensor_adc → tail_player |
| `scan` | sensor_msgs/LaserScan | LiDAR → tail_player |
| `cmd_vel` | geometry_msgs/Twist | tail_player → pinky_bringup |
| `tail/state` | std_msgs/String | tail_player → 기록 |

`cmd_vel`을 내는 노드는 `tail_player` 하나다.

## 5. 안전 규칙 (`tail_core`)

1. LiDAR 앞쪽 ±45° 안에서 로봇 몸체까지 0.10 m 이내에 물체가 있으면 전진을 멈춘다. 0.25 m 이내면 0.10 m/s 이하로 줄인다. 접근 중 꼬리가 정면 ±7° 안에 있을 때만 정면 ±15°를 제외한다(이 범위는 2번이 맡는다).
2. 초음파 거리가 태깅 거리 이하이면 태깅 여부와 관계없이 전진을 멈춘다. 0.30 m 이하이면 0.10 m/s 이하로 줄인다. 튄 값에 속지 않도록 최근 3개 중 가장 작은 값을 쓴다.
3. `scan`이 0.3초, 초음파 값이 0.2초 넘게 오지 않으면 정지한다.
4. 추격·접근 중 `tail/detection` 메시지가 0.5초 넘게 오지 않으면 정지한다. 미검출 메시지는 온 것으로 본다.
5. 속도 상한: 돌아다니기·추격 0.20 m/s, 접근 0.10 m/s, 회전 1.0 rad/s.
6. 후진은 태깅 직후에만 0.05 m/s 이하, 0.15 m 이내로 한다. LiDAR 뒤쪽 ±45° 안에서 몸체까지 0.20 m 이내에 물체가 있으면 후진하지 않고, 후진 중 0.05 m 이내가 되면 멈춘다. 벽을 피할 때는 후진하지 않고 제자리 회전한다.
7. PC의 시작·정지 메시지가 2초 넘게 오지 않으면 정지한다.

| # | 측정 | 이 값으로 정하는 것 |
|---|---|---|
| 1 | 꼬리가 보이는 범위: 상대 로봇을 30° 간격으로 돌려 놓고 0.2–2 m에서 검출 여부 | 태깅 조건, 찾는 방법 |
| 2 | 두 번째 로봇의 접속, 설치 버전, `pinkylib`, 부저 핀, LED, 카메라 방향 | 두 로봇에 같은 코드를 쓸 수 있는지 |
| 3 | 꼬리색·LED 밝기·카메라 노출 조합별 영상: 경기장 조명, 바닥 반사, 화면 속 다른 색 물체 | 꼬리색, 노출, 색 범위 |
| 4 | 거리별(0.05–2 m) 덩어리 폭, 카메라 시야각, 태깅 거리에서 꼬리가 화면 안에 들어오는지 | 방향·거리 변환, 근접 크기, 태깅 거리 |
| 5 | 초음파 값: 상대 로봇의 뒤·옆·앞 면을 0.05–0.5 m에서, 정면과 ±15°, ±30° 방향으로 | 태깅 거리, 연속 횟수 |
| 6 | 두 로봇의 초음파가 마주 볼 때와 앞뒤로 나란할 때의 값 변화 | 간섭 여부, 판정 필터 |
| 7 | LiDAR에 상대 로봇이 잡히는지(0.1–1.0 m) | 안전 규칙 1의 거리, §3.4 |
| 8 | bringup과 함께 실행할 때 `tail_tracker` 처리 속도와 CPU·메모리 | 영상 크기, 처리 주기 |
| 9 | 0.10, 0.15, 0.20 m/s에서 정지 거리와 제자리 회전 속도 | 속도, 정지 거리 |
| 10 | 두 로봇을 한 공유기에 연결했을 때 UDP 왕복 시간과 끊김 | §3.6 |
| 11 | 경기장 치수, 벽 높이(LiDAR 높이 이상), 바닥, 조명 | 3번의 촬영 조건, 제한 시간 |

- 1번에서 꼬리가 앞쪽에서도 보이면 LED 위에 가림막을 달거나 켜는 LED 개수를 줄여 뒤쪽에서만 보이게 한다.
- 4번에서 태깅 거리의 꼬리가 화면 밖이면 태깅 거리를 늘린다.
- 7번에서 LiDAR에 상대가 잡히지 않으면 마주칠 때 막아 주는 것이 초음파뿐이다. 돌아다니는 속도를 0.10 m/s로 낮추고, 6번에서 마주 본 초음파 값이 믿을 만한지 확인한 뒤에 올린다.
- 5번에서 초음파가 상대 뒷면을 재지 못하면 태깅 거리 판정을 LiDAR 정면 거리로 바꾸고 초음파는 보조로 쓴다.

## 7. 합격 기준과 불합격 시 절차

| 항목 | 기준 |
|---|---|
| 꼬리 검출: 정지한 상대의 뒤 0.15–1.5 m | 미검출 0.3초 이하 |
| 꼬리 오검출: 자기 꼬리를 켠 채 상대가 없는 경기장을 벽 가까이까지 돌며 촬영 | 0회 |
| 꼬리 오검출: 상대의 앞·옆을 볼 때 | 0회 |
| 태깅: 정지한 상대의 뒤로 접근 | 10회 모두 태깅, 충돌 0회 |
| 태깅: 움직이는 상대 | 10회 모두 태깅 |
| 벽 앞, 상대의 앞·옆 앞 | 각 20회 접근 중 오태깅 0회 |
| 마주침 | 20회 모두 닿지 않고 돌아 나감 |
| 벽·모서리 옆의 꼬리 추격 | 10회 모두 벽 충돌 0회 |
| 태깅 뒤 후진: 뒤가 벽인 자리에서 태깅 | 10회 모두 벽에 닿지 않음 |
| 부저·LED | 태깅 20회 모두 이긴 로봇 부저, 진 로봇 LED 꺼짐. 태깅 없이 울림 0회 |
| 메시지 끊김 주입(검출, 초음파, LiDAR, PC) | 각 10회 모두 기준 시간 안에 정지 |
| 연속 경기 | 10판 동안 벽 충돌 0회, 로봇끼리 충돌 0회, 사람 개입 0회 |

불합격이면 실패한 시행의 영상·검출 결과·초음파 값·LiDAR·명령 기록을 남기고, 원인(꼬리 검출, 초음파 값, 통신, 주행)을 분류해 고친 뒤 같은 조건으로 다시 시험한다.

## 8. 개발 순서

| 단계 | 내용 | 완료 조건 |
|---|---|---|
| 1 | 측정 스크립트, §6의 1–9번 측정 | 측정값 기록, 꼬리색·노출·태깅 거리 확정 |
| 2 | `tail_core`와 2D 모의 시험 | 돌아다니기·추격·태깅·마주침·맴돌기·끊김 정지 시험 통과 |
| 3 | `tail_tracker` | 꼬리 검출 합격 기준 |
| 4 | 드라이버 패치, 경기용 launch, `tail_player`(LED·부저 포함) | 명령을 끊으면 정지, 로봇 1대가 벽을 피하며 5분 주행 |
| 5 | 로봇 1대 + 정지한 상대 | 추격·접근·태깅·부저 |
| 6 | `tail_referee`, §6의 10–11번 측정 | PC에서 시작·정지, 끊기면 정지 |
| 7 | 로봇 2대 | §7 합격 기준 |

- 1단계와 2단계는 동시에 진행한다.
