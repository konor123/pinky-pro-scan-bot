# Pinky Tag — 술래잡기 SW 개발 계획서 v1.0

- 과제: Pinky Pro 2대의 술래잡기
- 요구: 기본 자율주행, YOLO로 상대 로봇 인식, 초음파 센서로 태깅 감지, 태깅 시 부저
- 기반: Pinky Pro 공식 저장소 `pinklab-art/pinky_pro` (main `014a09f`), `pinky_study` 교재
- 범위: 소프트웨어 개발과 시험 도구

---

## 1. 로봇이 하는 일

1. 벽으로 둘러싼 경기장 안에서 두 로봇이 각자 지도 위 자기 위치를 알고 주행한다.
2. 앞 카메라 영상에서 YOLO로 상대 로봇을 찾는다.
3. 술래는 경기장을 돌며 상대를 찾고, 보이면 쫓아간다. 도망자는 돌아다니다가 술래가 보이면 반대쪽으로 달아난다.
4. 술래가 상대에게 붙어 앞쪽 초음파 거리가 태깅 거리 이하가 되면 태깅이다.
5. 태깅되면 두 로봇이 멈추고 부저를 울린다.
6. 역할을 바꾼다. 새 술래는 5초 기다린 뒤 출발한다.
7. PC에서 시작·정지 명령을 보낸다.

## 2. Pinky Pro에서 쓰는 것

| 대상 | 내용 | 쓰는 방법 |
|---|---|---|
| `pinky_bringup` | 모터 구동(`cmd_vel`), 엔코더 `odom`, LiDAR 실행 | 그대로 쓰고 명령 timeout을 추가한다 |
| `pinky_navigation` | SLAM 지도 작성, AMCL, Nav2 | 그대로 쓴다. 경기장 지도를 한 번 만들어 두 로봇이 같이 쓴다 |
| `pinky_sensor_adc` | 초음파 → `us_sensor/range` (sensor_msgs/Range, 20 Hz) | 기본 실행에 없으므로 launch에 추가한다 |
| 카메라 | Picamera2로 읽는다(640×480). ROS 노드 없음 | `opponent_detector`가 카메라를 혼자 쓴다 |
| YOLO | 교재 방식: 사진 촬영 → Roboflow 라벨링 → Colab에서 YOLOv8 학습 → `best.pt` | 같은 순서로 상대 로봇 1개 클래스를 학습한다 |
| `pinkylib.Buzzer` | 부저 구동(`buzzer_start`, `buzzer(n)`, `set_buzzer_freq`, `set_buzzer_duty`, `buzzer_stop`, `clean`) | ROS 노드가 없으므로 `buzzer_node`를 새로 만든다 |
| `pinky_gz_sim` | Gazebo 시뮬레이터(`namespace`, `robot_name` 인자 있음) | 로봇 2대를 띄우고 초음파 센서를 추가한다. Nav2 설정은 로봇별로 따로 만든다 |

확인한 사실

- 로봇의 컴퓨터는 Raspberry Pi 5다. 교재의 부품 목록에 AI 가속기 Hailo-8L이 있다.
- Pinky Pro 교재에는 학습까지만 있고 로봇에서 추론하는 코드가 없다. `pinkylib.yolo.Yolo`(`set_model`, `detect_yolo`)는 Pinky Blue 교재에 나온다.
- 초음파 거리는 `ADC값 / 4096 − 0.03` m로 계산된다. 최댓값이 약 0.97 m다. 센서는 로봇 앞면 중앙에서 정면을 본다(시야각 0.26 rad).
- 초음파 값만으로는 앞에 있는 것이 벽인지 상대 로봇인지 구분할 수 없다.
- 모터 드라이버는 명령이 끊겨도 직전 속도로 계속 달린다.
- `bringup.py`의 토픽과 frame 이름(`odom`, `base_footprint`)이 고정돼 있고, 로봇용 launch에 namespace 인자가 없다.
- 공식 README에 따르면 여러 Pinky Pro를 한 공유기에 연결하면 DDS 통신량 때문에 끊김과 지연이 생긴다.
- Nav2 설정: footprint 0.12 × 0.12 m, inflation 0.15 m, 최대 속도 0.25 m/s.
- namespace를 주면 로봇 frame 이름에 접두어가 붙는데, Nav2 설정 파일은 `base_footprint`와 `/scan`으로 고정돼 있다. 한 시뮬레이터에 2대를 띄우면 그대로는 맞지 않는다.

## 3. 동작 원리

### 3.1 상대 로봇 인식 (YOLO)

- 클래스는 `pinky` 하나다. 두 로봇은 상대만 보므로 서로를 구분할 필요가 없다.
- 추론은 로봇 안에서 한다. 영상은 로봇 밖으로 보내지 않고 검출 결과만 발행한다.
- 검출 결과에서 두 값을 구한다.
  - **방향:** 박스 중심의 가로 위치 → 정면 기준 각도
  - **거리:** 박스 높이 → 거리. 거리별 박스 높이를 측정해 변환표를 만든다
- 검출 결과는 매 영상마다 발행한다. 상대가 없으면 '미검출'로 발행한다.
- 필요한 속도는 초기값 5 Hz 이상이고, 추격 시험에서 확정한다. `best.pt` 그대로의 속도를 먼저 재고, 모자라면 입력 크기 축소 → NCNN 변환 → Hailo-8L 순서로 올린다.

**학습 데이터**

| 항목 | 내용 |
|---|---|
| 촬영 | 로봇의 카메라로, 경기장 위에서 상대 로봇을 찍는다 |
| 조건 | 거리 0.05–2 m, 앞·옆·뒤·사선, 화면 가장자리에 걸친 모습, 가까워서 일부만 보이는 모습, 시연 장소 조명 |
| 수량 | 300장 이상. 로봇이 없는 경기장·벽·사람 발 사진 50장 이상 포함 |
| 라벨링·학습 | Roboflow, YOLOv8n, train:valid:test = 7:2:1 |

### 3.2 자율주행

- 경기장 지도를 SLAM으로 한 번 만든다. 두 로봇이 같은 지도 파일로 AMCL과 Nav2를 실행한다.
- 시작 전에 두 로봇을 정해진 출발 위치에 놓고 초기 위치를 준다.
- 경기장에 순찰 지점을 6–8개 정해 둔다.
- 상대가 보이지 않을 때의 이동은 Nav2 목표로 한다. 벽 회피는 Nav2가 한다.

### 3.3 술래

1. **탐색:** 순찰 지점을 차례로 Nav2 목표로 준다. 지점에 도착하면 제자리에서 한 바퀴 돈다.
2. **추격:** 상대가 검출되면 Nav2 목표를 취소한다. 검출 방향으로 몸을 돌리며 전진한다. 전진은 최근 0.3초 안에 검출이 있을 때만 하고, 없으면 제자리에 선다.
3. **접근:** 검출 거리나 초음파 거리가 접근 거리(초기값 0.5 m) 이하가 되면 저속(초기값 0.10 m/s)으로 줄인다.
4. **태깅:** 접근 중 다음 두 조건이 함께 3회 연속 성립하면 태깅이다.
   - 초음파 거리가 태깅 거리(초기값 0.10 m) 이하
   - 최근 0.5초 안에 상대가 화면 중앙(±15°)에서 근접 크기 이상으로 검출됨
5. 태깅하면 정지하고, 태깅 메시지를 보내고, 부저를 울린다.
6. 미검출이 1초 넘게 이어지면 마지막으로 본 방향으로 제자리에서 돌아 보고, 다시 보이지 않으면 탐색으로 돌아간다.

두 번째 조건이 벽과 상대 로봇을 구분한다.

### 3.4 도망자

- 순찰 지점 사이를 Nav2로 돌아다닌다.
- 술래가 검출되면 검출 방향·거리와 내 위치로 술래의 지도상 위치를 계산한다. 그 위치에서 가장 먼 순찰 지점을 Nav2 목표로 준다. 술래 쪽을 지나가야 하는 지점은 제외한다.
- 도망자 최대 속도는 술래보다 낮게 둔다(초기값: 술래 0.20 m/s, 도망자 0.15 m/s).
- 태깅 메시지를 받으면 정지하고 부저를 울린다.

### 3.5 태깅 후

- 술래는 짧게 2번, 잡힌 로봇은 길게 1번 부저를 울린다.
- 부저가 끝나면 두 로봇이 각자 0.15 m 후진해 떨어진다. 후진 속도는 0.05 m/s이고, 방금 지나온 길이므로 비어 있다.
- 역할을 바꾼다. 새 도망자는 후진을 마치면 출발하고, 새 술래는 5초 뒤 출발한다.
- PC에서 정지를 보낼 때까지 반복한다.

### 3.6 두 로봇의 연결

- 두 로봇과 PC를 같은 공유기에 연결한다.
- 로봇마다 `ROS_DOMAIN_ID`를 다르게 준다. 각 로봇은 공식 스택을 이름 변경 없이 그대로 실행하고, 두 로봇의 DDS 통신이 섞이지 않는다.
- 로봇 사이와 PC 사이에는 게임 메시지만 UDP로 주고받는다.

| 메시지 | 보내는 쪽 → 받는 쪽 | 주기 | 내용 |
|---|---|---|---|
| 태깅 | 술래 → 도망자, PC | 응답을 받을 때까지 반복 | 태깅 번호 |
| 시작·정지 | PC → 두 로봇 | 2 Hz로 계속 | 경기 중 / 정지, 첫 술래 |
| 상태 | 로봇 → PC | 2 Hz | 역할, 상태, 지도 위치, 검출 결과 |

## 4. 소프트웨어 구성

패키지는 `pinky_tag` 하나다. `pinky_pro`는 fork해서 패치한다.

| 구성 요소 | 하는 일 |
|---|---|
| `opponent_detector` | 카메라를 읽고 YOLO로 상대를 검출한다. 방향·거리·신뢰도를 발행한다 |
| `tag_core` | 역할 상태기계, 탐색·추격·접근·태깅 판정, 도피 지점 선택, 안전 규칙(ROS 비의존) |
| `tag_player` | 로봇마다 1개. 검출 결과·초음파·AMCL 위치를 받아 `tag_core`를 돌리고, Nav2 목표와 `cmd_vel`을 낸다. 게임 메시지 송수신 |
| `buzzer_node` | 부저 GPIO를 혼자 쓴다. `buzzer` 토픽을 받아 울린다 |
| `tag_referee` | PC에서 실행. 시작·정지 명령, 두 로봇 상태와 태깅 기록 표시·저장 |
| 데이터 도구 | 주행하며 일정 간격으로 사진을 저장하는 촬영 스크립트, 검출 속도·정확도 측정 스크립트 |
| 시뮬레이터 확장 | Gazebo에 로봇 2대와 경기장 world, 초음파 센서 추가. 검출 결과는 시뮬레이터의 실제 위치로 계산한 값을 같은 토픽으로 낸다 |

**패치**

| 대상 | 현재 동작 | 패치 |
|---|---|---|
| `pinky_bringup/bringup.py` | 명령이 끊겨도 직전 속도로 계속 주행 | 마지막 명령 이후 0.5초가 지나면 정지 |
| 로봇용 launch | 초음파 노드가 기본 실행에 없음 | `pinky_sensor_adc` 추가 |

**토픽 (로봇 1대 안)**

| 토픽 | 타입 | 생산 → 소비 |
|---|---|---|
| `opponent/detection` | geometry_msgs/PointStamped (x 거리, y 방향, z 신뢰도. 미검출이면 z = 0) | opponent_detector → tag_player |
| `us_sensor/range` | sensor_msgs/Range | pinky_sensor_adc → tag_player |
| `scan` | sensor_msgs/LaserScan | LiDAR → tag_player, Nav2 |
| `amcl_pose` | geometry_msgs/PoseWithCovarianceStamped | AMCL → tag_player |
| `navigate_to_pose` | nav2_msgs/action/NavigateToPose | tag_player → Nav2 |
| `cmd_vel` | geometry_msgs/Twist | Nav2(탐색·도피), tag_player(추격·접근·후진) → pinky_bringup |
| `buzzer` | std_msgs/String | tag_player → buzzer_node |
| `tag/state` | std_msgs/String | tag_player → 기록 |

추격·접근·후진 중에는 Nav2 목표가 취소된 상태이므로 `cmd_vel`을 내는 쪽은 한 번에 하나다.

## 5. 안전 규칙 (`tag_player`)

추격·접근 중에는 Nav2가 꺼져 있으므로 1–5번이 충돌을 막는다.

1. 초음파 거리가 태깅 거리 이하이면 태깅 여부와 관계없이 전진을 멈춘다.
2. LiDAR 앞쪽 ±45° 안에서 로봇 몸체까지 0.10 m 이내에 물체가 있으면 전진을 멈춘다. 0.25 m 이내면 접근 속도로 줄인다. 검출된 상대 방향 ±15°는 제외한다(상대는 1번이 맡는다).
3. 초음파 값이나 LiDAR `scan`이 0.2초 넘게 오지 않으면 정지한다.
4. `opponent/detection` 메시지가 0.5초 넘게 오지 않으면 정지한다. 미검출 메시지는 온 것으로 본다(미검출일 때의 동작은 §3.3).
5. 추격 속도는 0.20 m/s 이하, 접근 속도는 0.10 m/s 이하다.
6. 태깅 뒤 후진은 0.05 m/s 이하, 0.15 m 이내다.
7. PC의 시작·정지 메시지가 2초 넘게 오지 않으면 정지한다.
8. AMCL 위치의 분산이 기준을 넘으면 정지하고 PC에 알린다.

- 9번에서 끊김이 심하면 두 로봇을 각자의 AP에 두고, PC가 무선 어댑터 2개로 양쪽에 연결해 게임 메시지를 중계한다.

## 7. 합격 기준과 불합격 시 절차

| 항목 | 기준 |
|---|---|
| YOLO 검출(시험 사진) | 재현율 95% 이상, 로봇 없는 사진에서 오검출 0 |
| YOLO 검출(주행 중, 0.1–1.5 m 정면 ±25°) | 연속 미검출 0.5초 이하 |
| 검출 속도 | Nav2와 함께 5 Hz 이상(초기값) |
| 태깅 감지: 정지한 상대의 앞·옆·뒤로 접근 | 각 10회 모두 태깅, 충돌 0회 |
| 태깅 감지: 움직이는 상대 | 10회 모두 태깅 |
| 벽 앞 | 벽을 향해 접근 20회 중 오태깅 0회 |
| 벽·모서리 옆에 있는 상대를 추격 | 10회 모두 벽 충돌 0회 |
| 태깅 뒤 재출발 | 20회 모두 두 로봇이 닿지 않고 떨어져 출발 |
| 부저 | 태깅 20회 모두 두 로봇에서 울림, 태깅 없이 울림 0회 |
| 메시지 끊김 주입(검출, 초음파, LiDAR, PC) | 각 10회 모두 기준 시간 안에 정지 |
| 연속 경기 | 5분 동안 역할 교대 5회 이상, 벽 충돌 0회, 사람 개입 0회 |

불합격이면 실패한 시행의 영상·검출 결과·초음파 값·명령 기록을 남기고, 원인(검출, 초음파 값, 위치 오차, 통신, 주행)을 분류해 고친 뒤 같은 조건으로 다시 시험한다. 검출 실패는 실패한 장면의 사진을 학습 데이터에 넣고 다시 학습한다.

## 8. 개발 순서

| 단계 | 내용 | 완료 조건 |
|---|---|---|
| 1 | 촬영 스크립트, 사진 촬영, 라벨링, 1차 학습 | 시험 사진 기준 통과 |
| 2 | §6 측정 | 측정값 기록, 초기값과 추론 방식 확정 |
| 3 | `tag_core`와 단위 시험 | 탐색·추격·접근·태깅·역할 교대·끊김 정지 시험 통과 |
| 4 | Gazebo에 로봇 2대, 경기장, 초음파 추가. 로봇별 Nav2 설정(frame 접두어, `scan` 토픽) | 두 로봇이 각자 Nav2 목표로 주행 |
| 5 | `tag_player`, `tag_referee` | 시뮬레이터에서 5분 연속 경기 |
| 6 | `opponent_detector`, 드라이버 패치, `buzzer_node`, 로봇용 launch | 검출 5 Hz 이상, 명령을 끊으면 정지, 토픽으로 부저 울림 |
| 7 | 로봇 1대 + 정지한 상대 | 탐색·추격·접근·태깅·부저 |
| 8 | 로봇 2대 | §7 합격 기준 |

- 1–2단계와 3–5단계는 동시에 진행한다.
- 시뮬레이터와 로봇에 같은 `tag_player`를 쓴다.
- ROS 실행은 원격 PC(ROS 2 Jazzy)에서 한다.
