# Pinky Solar — SW 개발 계획서 v6.0

- 과제: Pinky Pro 기반 태양광 패널 청소 로봇 — 주행 MVP
- 시연: 2026-11-28(토)
- 조건: 평평한 직사각형 모형 패널. 청소 장치 없음.
- 기반: Pinky Pro 공식 저장소 `pinklab-art/pinky_pro` (Apache-2.0)
- 범위: 소프트웨어 개발과 시험 도구

---

## 1. 시연에서 로봇이 하는 일

1. 패널 모서리 근처에 놓인 로봇이 두 끝단을 차례로 찾아 출발 위치를 맞춘다.
2. 패널을 평행 왕복(직진 → 끝단에서 정지 → 줄 바꿈)으로 끝까지 주행한다.
3. 끝단은 로봇 앞쪽 바닥 IR 센서로 감지한다.
4. 마지막 줄 끝에서 정지한다.
5. 패널 밖으로 떨어지지 않는다.

## 2. Pinky Pro 저장소에서 쓰는 것

| 패키지 | 내용 | 쓰는 방법 |
|---|---|---|
| `pinky_bringup` | 모터 구동(`cmd_vel`), 엔코더 `odom` | 그대로 쓰고 명령 timeout을 추가한다 |
| `pinky_sensor_adc` | 바닥 IR 3채널 → `ir_sensor/range` | 기본 실행에 포함돼 있지 않으므로 launch에 추가하고, IR 읽기 주기를 올린다 |
| `pinky_imu_bno055` | BNO055 융합 자세 → `imu_raw` | 기본 실행에 포함돼 있지 않으므로 launch에 추가한다. 자세(orientation)의 yaw를 쓴다 |
| `pinky_mujoco` | MuJoCo 시뮬레이터(`odom`, `ground_truth`, 카메라) | 패널 world를 추가하고, IR과 `imu_raw` 출력을 추가한다 |
| `pinky_description` | URDF | 그대로 |

- 쓰지 않는 것: LiDAR, SLAM·Nav2, 카메라.
- 저장소에는 IR 값을 받아 정지하는 기능이 없다. IR 값을 쓰는 노드가 없고, 모터 드라이버는 `cmd_vel`만 받는다.
- IR 값의 범위(공식 테스트 코드 출력, 12비트): 반사면 220–290, 검은 면 2,800–3,700, 반사 없음 4,095.

## 3. 동작 원리

### 3.1 낙하 방지

- IR 3채널 중 하나라도 "지지면 없음"이면 전진을 멈춘다.
- **판정:** 원시값이 임계값 이상이면 지지면 없음으로 본다. 초기 임계값은 3,900이고, 실제 패널 표면과 끝단 밖에서 채널별로 측정해 확정한다. 히스테리시스를 둔다.
- **조건:** 주행 속도 0.08 m/s 이하. 감지에서 정지 명령까지 지연 0.15 s 이하(목표 0.08 s). 끝단 접근 각도는 수직에서 ±30° 이내.

### 3.2 줄 바꿈

IR이 끝단을 감지해 멈추면 바퀴 축은 끝단 약 20 mm 앞에 있다. 그대로 회전하면 뒤쪽 캐스터가 끝단 밖으로 나가므로 다음 순서로 한다.

1. 60 mm 후진한다(로봇 중심–끝단 약 80 mm).
2. 다음 줄 방향으로 90° 회전한다.
3. 줄 간격만큼 전진한다. 이때 IR은 반대편 측면 끝단을 향한다.
4. 같은 방향으로 90° 더 회전한다.

### 3.3 직진과 회전

- **Heading:** IMU 자세의 yaw로 유지한다. 회전도 yaw 기준 폐루프로 한다.
- **거리:** 후진 거리와 줄 간격은 바퀴 엔코더로 잰다.

### 3.4 왕복 패턴

**출발 정렬**

로봇은 패널 모서리 근처 안쪽에, IR 3채널이 모두 패널 위에 오도록 놓는다.

1. 한쪽 끝단을 향해 저속으로 전진한다. IR이 감지하면 정지하고 60 mm 후진한다.
2. 90° 회전해 측면 끝단을 향한다. 같은 방식으로 감지·정지·후진한다.
3. 90° 회전해 첫 줄 방향을 본다.

**반복**

1. 줄 방향으로 직진한다. IR이 끝단을 감지하면 정지한다.
2. §3.2의 줄 바꿈을 한다.
3. 줄 간격을 전진하는 도중 IR이 측면 끝단을 감지하면, 정지·후진한 뒤 그 위치를 마지막 줄로 한다.

**종료:** 마지막 줄의 끝단에서 정지하고 60 mm 후진한다.

### 3.5 시뮬레이션 확인 결과

저장소의 MuJoCo 물리 모델에 2.4 × 1.2 m 패널(높이 0.3 m)을 올리고, IR 위치에서 아래로 거리를 재는 방식으로 확인했다. Heading은 시뮬레이터의 실제 yaw를 썼다.

| 시험 | 결과 |
|---|---|
| 정지 없이 0.08 m/s 직진 | 추락 |
| IR 정지, 0.05 m/s | 바퀴 축–끝단 남은 거리 27 / 24 / 21 mm (지연 0.03 / 0.08 / 0.15 s) |
| IR 정지, 0.08 m/s | 25 / 21 / 15 mm |
| IR 정지, 0.12 m/s | 21 / 15 / 6 mm |
| IR 정지, 0.20 m/s | 12 / 2 mm / 추락 |
| 줄 바꿈, 후진 0 또는 30 mm | 실패(캐스터가 끝단 밖으로 나감) |
| 줄 바꿈, 후진 60 mm | 성공(캐스터–끝단 여유 24 mm) |
| 사선 접근 15° / 30° (0.08 m/s, 지연 0.08 s) | 정지. 가까운 쪽 바퀴 여유 13 / 6 mm |
| 사선 접근 45° / 60° | 한쪽 바퀴가 끝단을 넘음 |

| 전체 왕복(줄 간격 0.06 m) | 20줄, 15.3분, 93.6% |

## 4. 소프트웨어 구성

패키지는 `solar_bot` 하나다. `pinky_pro`는 fork해서 패치한다.

| 구성 요소 | 하는 일 |
|---|---|
| `fall_guard` | 모터로 가는 유일한 명령 경로. IR 판정, 속도 상한, 후진·회전 제한(§5) |
| `sweep_runner` | 출발 정렬, 줄 주행, 줄 바꿈, 종료 상태기계. Heading 유지와 회전 제어 |
| `solar_core` | 위 노드의 계산 로직(ROS 비의존) |
| 시뮬레이터 확장 | `pinky_mujoco` bridge에 IR(아래 방향 ray 3개 → `ir_sensor/range`)과 `imu_raw` 발행 추가. 패널 world |
| 평가 도구 | 궤적으로 덮은 면적과 줄 간격 오차를 계산. 시뮬레이터는 `ground_truth`, 실기는 패널 위에 고정한 D455 영상을 쓴다 |

**드라이버 패치**

| 대상 | 현재 동작 | 패치 |
|---|---|---|
| `pinky_bringup/bringup.py` | 명령이 끊겨도 직전 속도로 계속 주행 | 마지막 명령 이후 일정 시간이 지나면 정지 |
| `pinky_sensor_adc` | 20 Hz로 5채널을 읽고, 한 번에 30 ms 동안 멈춤 | IR 3채널을 40–50 Hz로 읽음 |
| launch | IR 노드와 IMU 노드가 기본 실행에 없음 | 로봇용 launch에 두 노드 추가 |

**토픽**

| 토픽 | 타입 | 생산 → 소비 |
|---|---|---|
| `ir_sensor/range` | std_msgs/UInt16MultiArray | pinky_sensor_adc → fall_guard |
| `imu_raw` | sensor_msgs/Imu | pinky_imu_bno055 → sweep_runner |
| `odom` | nav_msgs/Odometry | pinky_bringup → sweep_runner, fall_guard |
| `cmd_vel_req` | geometry_msgs/Twist | sweep_runner → fall_guard |
| `cmd_vel` | geometry_msgs/Twist | fall_guard → pinky_bringup |
| `fall_guard/state` | std_msgs/String | fall_guard → sweep_runner, PC |
| `sweep/state` | std_msgs/String | sweep_runner → PC |
| `stop` | std_msgs/Empty | PC → fall_guard |

## 5. 안전 규칙 (`fall_guard`)

1. 모터 명령은 `fall_guard`만 보낸다. 명령은 주기적으로 계속 보내고, 드라이버는 명령이 끊기면 정지한다.
2. IR 한 채널이라도 지지면 없음이면 전진 명령을 0으로 한다.
3. IR 감지로 멈춘 뒤에는 60 mm 후진을 마쳐야 회전과 전진을 통과시킨다.
4. 후진은 IR 감지 직후에만, 0.03 m/s 이하, 0.08 m 이내로 통과시킨다.
5. IR 값이 0.1 s 넘게 오지 않으면 정지한다.
6. 속도 상한: 직진 0.08 m/s, 회전 0.4 rad/s.
7. `stop`을 받으면 정지한다.

## 6. 끝단 감지 합격 기준과 불합격 시 절차

**합격 기준 (실제 모형 끝단, 완충 매트 위)**

| 항목 | 기준 |
|---|---|
| 정면 접근 0.08 m/s | 20회 모두 패널 위에서 정지 |
| 사선 접근 ±15°, ±30° | 각 10회 모두 정지 |
| 패널 내부 주행 | 전체 왕복 1회 동안 오정지 0회 |
| IR 값 끊김 주입 | 10회 모두 정지 |
| 감지에서 정지 명령까지 지연 | 0.15 s 이하 |

**불합격 시 (합격할 때까지 반복)**

1. 실패한 시행의 IR 원시값·속도·명령 기록을 남긴다.
2. 원인을 분류한다: 임계값, 표면 반사, 지연, 접근 각도.
3. 원인에 맞게 고친다.
   - 채널별 임계값과 히스테리시스 재설정
   - IR 읽기 주기 상향, 판정 필터 조정
   - 센서 보드의 감도(가변저항)·높이 조정 요청
   - 표면에서 IR로 구분이 안 되면 카메라로 끝단을 검출하는 기능을 추가
4. 같은 조건으로 다시 시험한다.

## 7. 개발 순서

### 7.1 시뮬레이터에서 먼저 완성한다

| 시나리오 | 확인하는 것 |
|---|---|
| 속도 × 지연별 끝단 정지 | §3.1 조건의 여유 |
| 줄 바꿈(후진 거리별) | 캐스터 여유 |
| 사선 접근 | 허용 각도 |
| 전체 왕복(출발 위치·방향을 바꿔 가며) | 완주, 덮은 면적, 소요 시간 |
| yaw 오차·바퀴 미끄럼·IR 지연 주입 | 줄 간격 오차, 마지막 줄 처리, 여유 |
| IR 값 끊김 | 정지 |

- 물리·로직 시험은 화면 없이 돌린다(개발 PC, ROS 불필요).
- 노드 시험은 원격 PC의 ROS 2 Jazzy에서 한다. 시뮬레이터와 실제 로봇에 같은 노드를 쓴다.

### 7.2 로봇에서 측정하고 맞춘다

| # | 측정 | 이 값으로 정하는 것 |
|---|---|---|
| 1 | IR 원시값: 패널 표면(셀 무늬, 광택 포함)과 끝단 밖, 채널별 | 임계값, 히스테리시스 |
| 2 | IR 읽기 주기, 감지에서 정지까지 지연 | 주행 속도 |
| 3 | 0.05, 0.08 m/s에서 정지 거리 | 주행 속도 |
| 4 | IMU yaw: 정지 중 변화, 90° 회전 오차, 30초 직진 중 변화 | Heading 제어 이득, 줄 간격 |
| 5 | 패널 표면에서 후진 60 mm, 전진 80 mm의 실제 이동 거리 | 엔코더 보정 계수 |
| 6 | 설치된 pinky_pro 버전 | 패치 기준 |
| 7 | 원격 PC에서 로봇까지 접속, 코드 전달, 기록 회수 | 작업 경로 |
| 8 | 모형 실제 치수, D455 설치 높이(패널 전체를 보려면 1.5 m 이상) | 평가 범위 |

- 실기 시험은 낮은 단(완충 매트)에서 시작해 실제 모형으로 옮긴다.
