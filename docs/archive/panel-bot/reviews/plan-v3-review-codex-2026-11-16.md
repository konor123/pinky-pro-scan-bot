## 2. 검토 결론

이 계획은 단안 RGB의 한계를 인정하고 안전 제어를 Onboard에 두는 방향은 타당하지만, 현재 그대로는 구현·실험의 합격 계약으로 확정하기 어렵다.
가장 큰 문제는 안전한 SLAM 초기화 이동, 단안 좌표계의 Metric 변환, 패널 지도 생성이 서로 의존하면서 초기 안전 영역의 출처가 정해지지 않았다는 점이다.
Scale Alignment는 카메라와 차체의 서로 다른 궤적, 직선 이동의 관측 가능성, Loop Closure·새 지도 이후 변환 갱신을 포함해야 한다.
§5.6과 §6.2의 변환 곱은 일관된 좌표계 규약 아래 맞으므로 역행렬을 무조건 바꿀 필요는 없지만, 입력 Pose 방향과 시각을 명시하지 않으면 구현에서 틀릴 수 있다.
Keepout과 PointCloud2는 서로 다른 소비 경로이므로 변환 노드와 Nav2 설정을 확정해야 하며, 경계가 관측되지 않는 상태를 자유 공간으로 취급해서는 안 된다.
정지 거리 식은 직진의 출발점으로 적절하지만 회전, 오래된 영상, 제어 프로세스 중단 및 재개 절차까지 보장하지 않는다.
AprilTag는 유용한 기준 측정이나 같은 카메라의 공통 오차와 관측 구간 편향 때문에 독립적인 완전한 Ground Truth로 단정할 수 없다.
15일 일정에는 1,000장 데이터셋, 반복 시험, Jazzy Adapter 검증 및 Masking 구현의 작업량과 실패 시 범위 축소 기준이 빠져 있다.
필수 18건, 권장 8건, 선택 2건을 아래에 제시하며, 실제 장비와 실행 검증이 필요한 미확인 항목은 8개 묶음으로 분리했다.

## 4. 문서 내부 불일치 목록

아래는 모두 **일반 지식·문서 대조**이며, 상위 표의 지적을 다시 세지 않는다.

1. **Nav2 범위:** §1.2 49행은 Nav2 또는 자체 Follower지만, §7.3 666행과 §13 986행은 Nav2 통합을 요구한다(X-M17).
2. **SLAM 장애 정책:** §1.3 59행의 이상 시 정지와 §5.7 565행의 Wheel/IMU 운행은 장애 등급·시간 조건이 없으면 충돌한다(X-M06, X-M17).
3. **모듈 매핑 누락:** §8.2 729행의 `virtual_obstacle_publisher`가 §8.1 681–716행에 없지만 §8.3 748행에는 출력이 있고 §13 979행에는 산출물이 있다(X-R03).
4. **지도/검증 경로 누락:** §4.6 361–367행의 OccupancyGrid·Keepout, §7.2 649행의 경로, §11.4 927행의 AprilTag 기준 Pose를 §8.3 740–752행에서 찾을 수 없다. ‘주요 Topic’ 표라 생략 자체가 오류는 아니지만 구현 계약으로는 생산자/소비자 연결이 필요하다(X-M07, X-R03).
5. **불확실성 연결 누락:** §8.3 745행 PoseStamped→749행 PoseWithCovarianceStamped, §5.7 564행·§9.2 788행의 불확실성 판정 사이에 산출 규칙이 없다(X-M06).
6. **전역 평면 지도와 부트스트랩:** §7.1 638행은 4개 꼭짓점 지도를 가정하나 §12 943–944행은 위치 추정 후 패널을 인식한다. 지도 사전 제공 여부와 초기 운동 근거가 없다(X-M01).
7. **데이터셋과 D5 완료 기준:** §4.2 273–291행의 1,000장 학습/검수 요구가 §10 804행의 ‘Detection 결과 출력’과 연결되지 않는다(X-M16).
8. **필수 성공 조건과 시험:** §1.3 55행의 Metric Scale은 §11.2 889–893행에서 수치 판정이 없고, §1.3 59행의 통신 이상 정지는 §11.1 852–860행의 카메라 중단만으로 대체할 수 없다(X-M17).
9. **지원 장애물과 지도 모델:** §1.1 22행·§3.4 226–227행은 틈새·단차를 포함하지만 §7.1 638행은 외곽 사각형만 기술한다. 내부 위험 영역과 불연속 작업영역 정책이 필요하다(X-M15).
10. **평가와 배포 모드:** §6.1 584행은 ‘검증 모드’에서만 Marker Masking을 지정해, §11의 성능이 §12 데모에도 그대로 적용되는지 불명확하다(X-M13).
11. **EKF 배치:** §5.3 453–475행의 Local EKF가 §3.2 174–193행의 Onboard/Offboard 목록 어느 쪽에도 명시되지 않는다. Wheel/IMU ‘입력’이 EKF 실행 위치를 뜻하는지 정해야 한다(X-M06).

## 5. 유지할 점

- **단안 한계의 명시(§2.3 134–154행, §4.4 326–328행):** RGB만으로 Depth Profile을 동일하게 대체하거나 외부 3D 깊이를 복원한다고 주장하지 않은 점을 유지한다. **일반 지식.**
- **선행 연구와 실제 코드의 구별(§2.1–2.2 101–126행):** RGB-D·LiDAR 시뮬레이션 성능을 그대로 이식하지 않고 PointCloud2/timer 차이를 구별했다. 해당 입력 조건은 [논문 본문](https://link.springer.com/article/10.1007/s42452-026-08326-5), 코드 구조는 [공개 구현](https://github.com/OxyBloom/negativeobstacleavoidandance/blob/main/bot_camera/bot_camera/clean_yolo.py)에서 확인했다. **확인함.** 표의 모든 성능 숫자를 재검산한 것은 아니다.
- **Onboard 안전 처리(§3.2 176–195행):** 네트워크 왕복과 PC SLAM의 성공 여부를 로컬 경계 정지의 필수 경로로 두지 않은 구조는 유지한다. **일반 지식.**
- **세션 단위 데이터 분리(§4.2 291행):** 인접 프레임의 train/test 누출을 예방하는 설계다. **일반 지식.**
- **Local 연속성·Global 보정의 분리(§5.1 423–433행, §5.6 538–557행):** EKF의 연속적인 odom과 Visual 전역 보정의 책임을 분리한 방향은 적절하다. Scale·시각·리셋 계약을 보충한다. **일반 지식.**
- **변환 수식의 구성(§5.6 548–554행, §6.2 592행):** `T^a_b`가 b→a이면 Camera→Base와 Tag 기반 Pose의 곱 순서는 올바르다. 표기 정의와 실제 Adapter 의미를 보충하면 된다. **일반 지식.**
- **안전 거리의 출발점(§4.7 375–390행):** 지연·감속·거리 불확실성·여유와 footprint 외곽 기준을 포함한 점은 유지한다. 회전과 지연 꼬리까지 확장해야 한다. **일반 지식.**
- **관측 안 된 방향의 보수성(§4.3 306행, §7.3 672행):** 후방을 안전하다고 가정하지 않고 Swept Footprint를 검토하는 원칙은 적절하다. **일반 지식.**
- **개별 기능과 Mission 시험 분리(§11.1–11.3 850–915행):** 감지·위치 추정·Coverage를 구별하고 반복 측정하는 틀은 유지하되 각 분모와 합격 기준을 보완한다. **일반 지식.**

## 6. 확인하지 못한 항목

다음 **8개 묶음 모두 확인 필요**이며, 문서·소스 조회와 실기 통과를 구분한다.

1. **실기 BOM·드라이버:** §1.2 39–43행, §3.1 164–170행의 실제 장비 revision, 카메라·IMU·구동기 사양, 기존 TF/odom 소유자, firmware watchdog. [Pinky 공개 저장소](https://github.com/pinklab-art/pinky_pro)는 열었지만 보유 로봇과 대조하지 않았다.
2. **카메라와 기하 오차:** §3.3 203–215행, §4.4 312–326행의 실제 FOV/FPS/rolling-shutter 영향·intrinsic/extrinsic·유효 거리·반사 조건 오차. 재장착·차체 기울기에 대한 수치도 미확인이다.
3. **정지·구동:** §4.7 375–388행과 §9.2 781–790행의 최소 감속도·최대 지연·바퀴 Slip·회전 정지 외곽·통신/프로세스 중단 시 실제 모터 정지. 50mm 여유의 충분성을 승인하지 않았다.
4. **실제 Jazzy 빌드·실행:** §5.4 479행, §8.1 697행, §14.4 1040행의 선택 Adapter/ORB/의존 라이브러리 조합을 빌드하지 않았다. Jazzy 브랜치 문서가 존재하는 것과 본 장비에서 통과하는 것은 별개다.
5. **부하·통신:** §3.2 174–193행, §8.3 740–752행의 실제 PC/Pi 자원·동시 rosbag·압축/전송 지연·QoS 호환·시계 동기·열화. 특정 FPS나 기본 timeout 값을 단정하지 않았다.
6. **시각 위치 추정·Masking:** §5.4 492–500행, §5.5 514–523행, §6.1 584행의 실제 특징량·초기화·Scale 안정성·Loop Closure·재위치 성공·mask 영향. 반복 패널에서 요구 정확도를 달성하는지는 미측정이다.
7. **평가 기준의 실측 정확도·통계:** §6.1–6.4 580–627행, §11 864–915행의 태그 설치/측정 오차·GT 가시율·trial 독립성·실제 Coverage와 성공률. 논문 §2.1 91–99행의 모든 표 수치와 분할 수량은 이번 검토에서 원자료까지 재검산하지 않았다.
8. **인력·준비 상태·배포 설정:** §10 796–814행, §8.2 721–734행, §13 973–990행의 기존 데이터/모형/학습 자원·담당 인원·재사용 코드 배포 조건·최종 Nav2 plugin/BT/timeout 설정은 확정 자료가 없다. 따라서 15+5일의 달성 가능성은 확정하지 않았다.

검증 기록: 계획서와 공식 자료의 읽기 검토는 완료했다. 로봇 주행, 성능 수치 검증, Jazzy 빌드, 안전 정지 실험은 수행하지 않았으며 통과로 간주하지 않는다. 계획서 및 다른 기존 파일은 수정하지 않고 이 검토 파일만 생성했다.
