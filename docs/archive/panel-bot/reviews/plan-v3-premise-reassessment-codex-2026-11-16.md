# Pinky Solar — 실제 사용자 요구에 따른 전제 재검토

## 1. 판단 기준과 최신 확정 사항

검토자 Codex, 2026-11-16. 대상은 `docs/plan/PLAN-v3.0.md`이며 다른 검토자 보고서는 읽지 않았다. 기존 계획을 수정하지 않고 대안과 남은 결정을 제시한다.

사용자의 최초 요구는 **‘패널 청소 봇 만들기, Pinky Pro 사용’**이었다. 이후 coordinator를 통해 전달된 확정 사항은 **청소 수단 제외, 주행만 MVP, 평평한 모형, 28일 시연**이다. ‘28일’은 **2026-11-28(토)**로 해석한다. 11/16부터 포함하면 달력 13일, 평일 10일이며 기존 15작업일+예비5일은 이 마감과 맞지 않는다. 인원과 모형·로봇·PC의 준비 상태는 미확인이다. D455 사용과 기존 센서 재사용은 허용 가능한 선택이며 단안·무LiDAR 연구 성과는 필수가 아니다.

**권고:** 사전 실측한 평평한 직사각형 영역에서, 기존 Wheel/IMU와 검증된 전역 위치 입력 하나를 사용해 저속 왕복 주행을 완성한다. 전역 위치 입력은 **기존 LiDAR+기존 항법을 우선 시험하되 11/18에 통과하지 못하면 D455 외부 고정 태그 위치 측정으로 단일 전환**한다. 끝단 안전은 사전 지도·보수적 운행 영역·Onboard 명령 gate·기존 IR의 실측 검증으로 구성하며, IR만으로 추락 방지를 보장하지 않는다. ORB-SLAM3·Scale Alignment·YOLO 학습·신규 RGB-D SLAM은 이번 필수 범위에서 제외한다.

근거 표기: **확인함**=공식 소스 직접 확인+링크, **일반 지식**=설계·물리·통계 원리, **추정**=아직 검증 전인 일정·계산, **확인 필요**=실물·실행 또는 사용자 조건 미확인. 공식 Pinky 자료 확인 시각은 **2026-11-16 05:24–05:26 UTC**이며, 공개 main과 설치된 버전이 같다고 가정하지 않는다.

## 3. 기존 자산에서 직접 확인한 것

- **확인함:** [Pinky bringup launch](https://github.com/pinklab-art/pinky_pro/blob/main/pinky_bringup/launch/bringup_robot.launch.xml)는 `sllidar_c1_launch.py`를 포함한다. LiDAR를 새로 구현하기보다 이 경로를 검증할 수 있다.
- **확인함:** [기존 드라이버](https://github.com/pinklab-art/pinky_pro/blob/main/pinky_bringup/pinky_bringup/bringup.py)는 Twist `cmd_vel`, odom child `base_footprint`, TF 발행을 사용한다. EKF 추가 시 기존 발행과 충돌하지 않도록 TF 단일 소유자를 정해야 한다.
- **확인함:** [pinky_navigation bringup](https://github.com/pinklab-art/pinky_pro/blob/main/pinky_navigation/launch/bringup_launch.xml)에 map server/AMCL/Nav2 연결이 있고 [map_building launch](https://github.com/pinklab-art/pinky_pro/blob/main/pinky_navigation/launch/map_building.launch.xml)는 slam_toolbox를 실행한다. 패키지 존재가 현장에서의 성능 검증은 아니다.
- **확인함:** [URDF](https://github.com/pinklab-art/pinky_pro/blob/main/pinky_description/urdf/pinky.urdf.xacro)는 IR 중심 `(0.0295,0,-0.015)`와 좌우 y=±0.02m, 바퀴 y=±0.04055m를 기술한다. 이 위치 정보만으로 IR 광축·유효 sensing footprint·실제 접지/제동 여유가 보장되지는 않는다.
- **확인함:** [upload launch](https://github.com/pinklab-art/pinky_pro/blob/main/pinky_description/launch/upload_robot.launch.py)는 `cam_tilt_deg=0`을 넘기지만 [robot xacro](https://github.com/pinklab-art/pinky_pro/blob/main/pinky_description/urdf/robot.urdf.xacro) 단독 기본값은 8이다. 실제 실행 경로를 고정해야 한다. 기본 카메라가 하향 지지면을 충분히 보는지는 **확인 필요**다.
- **확인 필요:** coordinator가 원문 대조한 TCRT5000 3개·US-016·BNO055/`imu_raw` 등의 사양은 실물과 설치 드라이버에서 다시 확인해야 한다. 본 검토는 해당 센서 실행 및 전기적 특성을 시험하지 않았다.

## 4. 권고 MVP 구성과 대안

### 권고 구성

| 기능 | 이번 구현 | 근거·실패 시 처리 |
|---|---|---|
| 작업 영역 | 사전 실측한 **연속·평평한 직사각형**. 내부 구멍/틈새 없이 시작 위치와 map 등록을 고정. | **일반 지식:** 온라인 외곽 발견과 초기 SLAM 운동의 순환 의존성을 없앤다. 실측 지도 기반 주행이라고 공개하며 자동 패널 인식으로 표현하지 않는다. |
| Local 위치 추정 | 기존 Wheel odom 검증, IMU 각속도 보정/EKF는 축·시간·공분산 검증 후 적용. `odom→base_footprint` 단일 발행자. | **일반 지식:** 이미 metric인 wheel 기준을 활용한다. Wheel-only라도 짧은 경로 오차가 허용되면 MVP 가능하지만 허용 면적·길이를 축소한다. |
| Global 위치 추정 | 우선 기존 LiDAR+slam_toolbox로 **주변 정적인 벽/특징 지도**를 만들고 사전 지도 localization. 패널 좌표를 이 지도에 측량 등록. | **일반 지식:** 스캔 평면에서 벽·구조물을 실제로 볼 수 있어야 한다. 평평한 패널 끝단은 그 자체로 LiDAR 벽이 아니다. 환경 특징 부족/높이 변화/가림으로 실패하면 외부 태그 위치 입력으로 전환. |
| 끝단 안전 | map상 패널을 로봇/가상도구 footprint·위치오차·정지 여유로 축소, 확인된 영역 밖 진입 금지. Onboard gate와 독립적인 모터 command timeout. 기존 하향 IR은 **지지면 변화의 추가 veto**로 실측 후 사용. | **일반 지식:** 지도와 감지는 상보적이다. IR은 반사 강도 센서 특성·재질·조명에 민감할 수 있고 안쪽 3점으로 바퀴 경로 전체를 덮는다고 가정하면 안 된다. 미관측 후진/회전을 금지하고 turn footprint를 검사한다. |
| IR가 안전 게이트를 통과하지 못할 때 | 내부 보수 영역에서만 운행하고 실제 끝단 접근 과제를 제외. 낮은 모형/받침·비간섭 추락 방지 등 시험 보호 사용. 센서 위치 수정은 원인이 명확하고 시간이 충분할 때만. | **일반 지식:** 예방 장치는 연구상 감지 성공으로 세지 않는다. 안전성을 주장할 수 없는 실제 낙하 끝단 주행은 데모에서 빼야 한다. deadline 때문에 실패한 IR를 그대로 신뢰하지 않는다. |
| 주행·Coverage | 사전 생성 평행 왕복선과 안전한 연결 구간. 기존 Nav2가 통과하면 이용하되 자동 BackUp/Spin 복구를 안전 승인 없이 실행하지 않도록 구성. | **일반 지식:** 일반 장애물 분해·온라인 재계획을 제외한다. Nav2 실패 시 고정 경로 Follower 1개로 축소한다. 단순히 waypoint에 도착한 것을 sweep 성공으로 보지 않는다. |
| Coverage 측정 | 고정한 유효 작업 면적을 분모, 실제 궤적을 따라 가상 폭이 덮은 면적의 합집합을 분자. 외부 D455 RGB 태그 관측을 우선 평가 수단으로 검토. | **일반 지식:** 겹침 중복·중단 trial·미관측 구간을 분리한다. 외부 태그를 위치 제어에도 썼다면 같은 Pose를 독립 정확도 GT로 쓰지 않고 별도 실측 지점/오차 예산으로 평가한다. |
| 청소 수단 | **없음. 가상 청소 폭만 사용.** | 최신 사용자 확정. ‘실제 패널을 청소했다’고 발표하지 않는다. |
| D455 | 기본은 외부 평가. LiDAR 불통과 시 외부 고정 태그 관측을 주행 위치 입력으로 전환하는 조건부 대안. | **일반 지식:** 차체 질량·Min-Z·USB 부하를 피한다. 외부 신호 단절/가림에서는 Onboard 정지. 신규 onboard RGB-D SLAM은 이번 기한에서 제외. |

### 대안 비교

| 대안 | 장점 | 주요 위험 | 11/28 판단 |
|---|---|---|---|
| **기존 LiDAR+Wheel/IMU+사전 지도** | 기존 패키지 재사용, metric 위치, 외부 카메라 없이 운행 가능 | 주변 구조물 관측·지도 등록·AMCL 안정성, LiDAR는 cliff 감지 대체 불가 | **1차 선택.** 11/18 위치 안정성 게이트를 통과해야 함. |
| **외부 D455 RGB 태그 위치+Wheel/IMU** | 복잡한 SLAM을 생략, 패널 좌표 직접 등록, 차체에 D455 탑재 불필요 | 전체 시야·가림·동기·통신 의존, 외부 인프라 한정 | **단일 대체 경로.** 11/19까지 위치 가시성과 정지 연계가 안 되면 더 축소. |
| **Wheel/IMU만, 작은 내부 경로** | 통합이 단순하고 네트워크 의존이 작음 | 누적 drift·횡방향 오차, 전체 영역 장기 Coverage 보장 어려움 | **축소 데모.** 짧은 검증 경로·고정 시작점·큰 여유·반복 reset, 광역 자율 Coverage와 구분. |
| **기본 RGB 단안 SLAM 또는 D455 RGB-D SLAM** | 비전 연구와 자립 항법 확장 가능 | 새 Adapter·동기/TF·추적·초기화·탑재 검증, 실제 준비 상태 불명 | **이번 필수 제외.** 이미 검증된 실행 자산이 있다는 증거가 있을 때만 재평가. |

모든 일정 적합성은 **추정**이다. 기존 부품·패키지가 있다는 사실만으로 10평일 내 성공을 보증하지 않는다. 특히 실내 주변 지도가 확보되지 않는 상황에서 LiDAR를 무조건 최선이라고 고집하지 않고 초기 게이트로 결정한다.

## 7. 남은 사용자 결정·필요 정보

이미 결정된 **Pinky Pro·청소 제외·평평한 모형·주행 MVP·28일 목표**는 다시 묻지 않는다. 단안/Depth 배제 해제도 추가 승인이 필요하지 않다.

1. **외부 인프라 허용 범위:** D455/태그를 평가에만 쓸지, LiDAR 실패 시 위치 제어 입력으로도 허용할지. 후자를 허용하면 시연 안정성을 우선하는 단일 대안이 생긴다.
2. **실험장 준비 상태:** 모형이 이미 있는지, 크기·표면·끝단 높이·주변 벽/가림·시연 장소는 무엇인지. 평평함만으로 end-of-panel 안전 문제가 없어지지는 않는다.
3. **담당 인원·작업 가능 시간·장비 상태:** 10평일 게이트의 현실성을 결정한다. 현재 미확인이므로 완료 확약은 하지 않는다.
4. **최종 시연 최소 범위:** 내부 왕복+가상 Coverage면 충분한지, 실제 끝단 접근/정지가 반드시 필요한지. 후자는 안전 게이트 불통과 때 제외해야 한다.

## 8. 검증 한계
